Control Gateway Architecture

Current architecture of control-gateway, the Rust runtime that lets Control operate against local folders and repositories on SSH boxes while keeping privileged process, credential, and protocol details in the main process.

Working name Control Relay Current binary control-gateway Module directory crates/C-Gateway

Process Map

Renderer requests go through typed IPC. Main owns gateway lifecycle and credentials.

Renderer Main process Gateway runtime Host root Native commands

Rust Runtime Modules

The public interface is GraphQL today, backed by repository and operation modules.

State And Secrets

SQLite stores reconstructable metadata. Keychain stores gateway tokens.

Startup Graph

Local and SSH gateway startup share the same contract: credentials, runtime start, manifest, verify, persist.

Gateway To Relay Expansion

The current runtime is repository-first. The next architecture should expose host capability modules without adding a generic shell bridge.

Current fit

GraphQL works well for repository reads and simple mutations.

Next pressure

Long-running host work needs task identity, cancellation, progress, and typed failure results.

Design guardrail

Broaden capabilities through typed modules, not through a catch-all shell route.
